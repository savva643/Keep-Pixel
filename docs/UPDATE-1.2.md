# Keep Pixel 1.2 — подключение по IP и клиент-лаунчер

На сервере владельца подтверждены адреса:

- Keep Pixel API: `http://85.112.56.145:4002` — `/health` и реальный каталог отвечают 200.
- Necsoura Auth: `http://85.112.56.145:3001/api/auth` — `POST /prelogin` отвечает 200.
- Сайт аккаунта: `http://85.112.56.145`.

Прежний адрес `necsoura.ru` отвечает парковочной страницей регистратора. Маршрут `http://85.112.56.145/api/keeppixel/health` на момент диагностики возвращал 404 сайта Next.js. Поэтому клиент по умолчанию подключается напрямую к **реально проверенным** портам Docker. В production-настройках нет localhost. Адреса меняются в настройках клиента без пересборки. При смене сервера токены сбрасываются и не отправляются новому хосту.

## Обновление сервера

Из корня Necsoura после слияния изменений:

```sh
git pull --ff-only
docker compose -f infra/docker/docker-compose.yml up -d --build kompot-backend friends-service keeppixel-backend
docker compose -f infra/docker/docker-compose.yml up -d --no-deps --force-recreate nginx
docker compose -f infra/docker/docker-compose.yml logs --tail=80 keeppixel-backend friends-service
curl --fail http://85.112.56.145:4002/health
```

Нужны **все три бэкенда**: Kompot получает API публичных профилей пачкой, friends-service — исправления заявок/блокировок, Keep Pixel — связку друзей, поиск и фильтры. Базы и тома не удаляются, новых миграций для 1.2 нет.

Если используется Nginx именно из `infra/docker/docker-compose.yml`, после пересоздания проверьте:

```sh
curl --fail http://85.112.56.145/api/keeppixel/health
```

После ответа `{"status":"ok"}` можно выбрать в настройках клиента «Через Nginx · порт 80». Конфигурация также проксирует `/api/auth/` и `/uploads/`. Если 404 сохранился, порт 80 обслуживает другая конфигурация/контейнер: прямое подключение клиента остаётся рабочим.

Для браузера бэкенд разрешает origin `http://85.112.56.145`. Если web-клиент размещён на другом адресе/порту, задайте точный `KEEP_PIXEL_CORS_ORIGINS` в `infra/docker/.env` и пересоздайте keeppixel-backend. `KEEP_PIXEL_PUBLIC_SERVER_URL` задаёт внешний адрес изображений (по умолчанию тот же IP).

## Обновление клиента

Из Keep-Pixel:

```sh
git pull --ff-only
flutter pub get
flutter run -d windows
```

Для сборки Windows: `flutter build windows --release` на Windows с Visual Studio C++ tools. Для web: `flutter build web --release --no-web-resources-cdn`.

В Windows сеанс сохраняется защищённым хранилищем. На обычном HTTP в браузере WebCrypto недоступен: вход работает, но токен хранится **только в памяти вкладки**, после перезагрузки нужен новый вход. Android разрешает HTTP адресно для `85.112.56.145`; общий запрет cleartext для других хостов сохранён. iOS/macOS native-сборки отдельно не проверялись; для постоянной эксплуатации используйте HTTPS.

## Изменения сценариев

- Навигация: магазин, библиотека, друзья, профиль, настройки и загрузки. Логотип — локально упакованный Unbounded, начертание 700, подмножество букв логотипа (2.8 KB).
- Библиотека: список своих игр, поиск, фильтр установленных; на ПК рядом открыта страница выбранной игры с «Играть / Установить / Обновить». Есть удаление файлов с подтверждением; лицензия остаётся в библиотеке.
- Установка больше не отменяется при уходе со страницы. Общая очередь последовательно устанавливает игры; можно отменить текущую/ожидающую, увидеть ошибку и повторить. Очередь действует в течение работы приложения; докачка после перезапуска не реализована.
- Друзья: поиск по публичному имени, username/id и псевдониму Keep Pixel; входящие/исходящие заявки, принятие, отклонение, отмена, удаление, блокировка и разблокировка. Общие друзья сохраняются между сервисами; статусы приходят из presence. Приватные логины и email через список/поиск не выдаются.
- Исправлен выбор получателя заявки при сортировке UUID. Чужую заявку принять нельзя; другой пользователь не может удалить или перезаписать вашу блокировку. Конкурирующие операции защищены SQL-условиями.
- Фото и псевдоним Keep Pixel учитываются в списке друзей. Ссылки `/uploads/` с внутренними Docker-хостами преобразуются во внешний адрес.
- Поиск, бесплатные/будущие игры и сортировка работают в SQL **до** постраничной загрузки. Добавлена явная кнопка обновления каталога.

Каталог не заполняется выдуманными релизами. Проверенный Keep Pixel Platform остаётся «В разработке»; кнопка установки появляется только при опубликованном валидном Windows-манифесте и лицензии. Платёжный провайдер, мобильный установщик и SDK Linux-приложений здесь не добавлялись.

## Проверка

Локально: Flutter API/виджеты/очередь и распаковка, Node API и настоящий PostgreSQL-движок PGlite, связка двух HTTP-сервисов Keep Pixel + friends-service. Общие Auth/Kompot/presence в интеграционных тестах заменяются контролируемыми ответами. Реальные пользовательские заявки, письма и уведомления на сервере не отправлялись.

Браузерный сценарий запускается на имитируемом origin `http://85.112.56.145`, где `isSecureContext=false` и `crypto.subtle` отсутствует; весь его трафик перенаправлен в локальный тестовый стек. Проверяются вход, отсутствие токена в localStorage, принятие заявки, получение бесплатной тестовой игры и библиотека. Тестовые пользователи/игры не входят в production-каталог.

На реальном сервере сделаны только публичные сетевые проверки адресов. Запуск реального Windows EXE на Linux-хосте не проверялся: после публикации релиза его нужно проверить на Windows.
